Mục tiêu của bạn là tạo ra bộ slide thuyết trình (Slide Deck) bài bản, chuẩn mực và thẩm mỹ cho dự án: "Team Matikanefukukitaru — AI-Powered Recruitment & Resume Reuse Portal".

## 2. QUY TẮC NGUYÊN TẮC THIẾT KẾ SLIDE (STRICT DESIGN BEST PRACTICES)
Bạn BẮT BUỘC tuân thủ các quy tắc thiết kế slide sau:
1. Quy tắc "1 Slide = 1 Mảnh Thông Tin" (Rule of One):
   - Mỗi slide CHỈ trình bày duy nhất 1 ý tưởng / 1 luồng / 1 thành phần kiến trúc chính.
   - KHÔNG gộp nhiều chủ đề không liên quan vào cùng một slide.
2. Ngắn gọn & Tốc độ đọc (Concise Bullet Points):
   - Mỗi slide chỉ tối đa 3 - 4 bullet points.
   - Mỗi bullet point tối đa 6 - 8 từ. Dùng câu chủ động, từ khóa chính (keywords).
   - KHÔNG dùng đoạn văn dài (wall of text).
3. Mô tả Visual/Diagram rõ ràng:
   - Slide nào có sơ đồ phải cung cấp mã Mermaid.js hoặc ASCII Diagram ngắn gọn, trực quan.
4. Cấu trúc phân cấp thông tin (Visual Hierarchy):
   - Tiêu đề slide (Slide Title) -> Thông điệp cốt lõi (Key Takeaway) -> 3-4 Bullets/Diagram.

## 3. TRI THỨC TOÀN DIỆN VỀ DỰ ÁN (PROJECT KNOWLEDGE BASE)

### A. Tổng quan & Vấn đề (Problem & Solution)
- Vấn đề Ứng viên: Mất thời gian tạo lại CV lặp đi lặp lại; Thiếu thông tin thị trường để tìm việc phù hợp.
- Vấn đề Nhà tuyển dụng: Đội chi phí lọc CV thủ công; Chỉ tiếp cận được CV nộp trực tiếp, thiếu matching thông minh.
- Giải pháp: Nền tảng tuyển dụng thông minh tích hợp Dual AI Agent (Ingest Agent + Matching Agent) trên nền LangGraph & Supabase pgvector.

### B. Tech Stack dự án
- AI / Agent: LangGraph, Qwen Cloud (DashScope API: qwen3.7-flash & qwen3.7-text-embedding).
- Backend: FastAPI (Python 3.11+), Pydantic v2, Uvicorn.
- Data & Auth: Supabase Local (PostgreSQL 15+, pgvector HNSW, Supabase Auth JWT, Storage).
- Frontend: React 19, Vite, TypeScript, Tailwind CSS v4, DnD Kit, jsPDF.

### C. Luồng xử lý & Flow Diagrams

1. System Data Flow:
   Frontend (React) --[REST/JWT]--> FastAPI Backend --[Service Role]--> Supabase Data/Storage
   FastAPI Backend <--> LangGraph Agents <--> Qwen Cloud LLM / Embedding

2. Ingest Agent Flow (LangGraph):
   [Start] -> parse (PDF/DOCX -> markdown) -> clean (Normalize text) -> extract (Skill taxonomy extraction) -> summarize (LLM summary + Redact PII) -> embed (Qwen 1536-dim vector) -> [END]

3. Matching Agent Flow (LangGraph):
   [Start] -> retrieve (pgvector semantic + FTS hybrid) -> skill (Skill coverage score) -> rrf (Reciprocal Rank Fusion) -> rerank -> explain (LLM rationale) -> respond (Summary answer) -> [END]

### D. ERD Database Schema (Supabase Postgres)
- public.profiles: id (FK -> auth.users), role (candidate/recruiter/admin), full_name, default_resume_id.
- public.profile_lines: id, profile_id (FK), category, key_name, value_text, is_active. (Tái sử dụng dữ liệu CV).
- public.resumes: id, profile_id (FK), file_path, parsed_markdown, status.
- public.embedded_resumes: resume_id (FK), embedding (vector 1536), skills (text[]), parsed_markdown.
- public.job_posts: id, company_id (FK), title, description, skills_required (text[]), status.
- public.job_submits: id, job_id (FK), resume_id (FK), candidate_id (FK), status.
- public.match_resume: id, job_id (FK), candidate_id (FK), final_score, rank.
- public.match_evidence: id, match_id (FK), factor_name, score, evidence_json.

### E. Class & Architecture Diagram (Backend Structure)
- Layer Architecture:
  - api/routes & api/schemas: Route handler, validate input, JWT auth verification.
  - services/ & repositories/: Pure business logic & database queries via Supabase client.
  - agents/: LangGraph graphs (ingest/graph.py, matching/graph.py) & State (AgentState).
  - clients/: LLM client (clients/llm.py) & Supabase Service Role client.
- State Class (AgentState):
  - TypedDict chứa: query, job_id, jd_skills, candidates, markdown, skills, embedding, match_reasons.
